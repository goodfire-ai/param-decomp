Strategy-robust PPGD speedups

Speedups that survive a distributed strategy in flux. Assumes: the 3-pool design is dropped, something simpler replaces it, the macro-strategy is likely parallel layerwise/chunkwise runs, and the topology will keep changing under us.  ·  2026-06-10  ·  supersedes ppgd_adversary_review.html where they conflict.

TL;DR. The way to make a speedup survive topology churn is to implement it at the layer every topology passes through: the PPGD kernel in param_decomp/metrics/persistent_pgd_{state,recon}.py. Every strategy — single-pool DDP, any pool split, a SLURM array of layerwise runs — ultimately calls the same three things: warmup(), compute_recon_sum_and_n(), and a source step. Changes inside that surface are inherited by whatever trainer wraps it; changes in trainer/topology code die with the trainer.

Three tiers. Tier 1 (strategy-proof, do these): vertex warm start + optimistic source extrapolation to justify n_warmup=0/1; tilted parallel sampling as a width-not-depth replacement for serial warmup; a cheap warmup objective with the exact joint loss kept for the final step; stateless or parameter-shaped sources (the source tensor is itself the least topology-robust object in the codebase); and porting the strategy-agnostic wins already written on feature/multipool back into core before they rot. Tier 2 (keyed to parallel layerwise/chunkwise runs — your stated likely macro-strategy): the frozen-suffix toolkit comes back to life — residual-start caching, near-exact cached-adjoint warmup, and suffix surrogates amortized across the whole run array. Tier 3 (topology-coupled, defer): staleness/async, pipelining, cross-pool sharding — but run the cheap staleness-tolerance experiment now, because its result derisks every future async strategy at once.

1 · Glossary

Sources / masks / warmup
Sources r ∈ [0,1] are the per-component values PPGD optimizes adversarially; the forward consumes masks m = g + (1−g)·r where g is the causal-importance (CI) value — so r=0 means "ablate as far as CI permits" and r=1 means "don't ablate". Warmup = the n_warmup_steps sequential gradient-ascent updates on the sources before the final loss; the final backward supplies one more, for n_warmup+1 source updates per training step.
Adjoint
The gradient of the loss with respect to an intermediate activation — e.g. ∂L/∂(output of a decomposed module). Backprop computes these on its way to parameter gradients. Because a decomposed module's output is linear in its masks (out = Σ_c m_c (a·V_c) U_c, with h_c = a·V_c the inner activation you already compute for CI), the source gradient is ∂L/∂r_c = (1−g_c)·h_c·⟨U_c, adjoint⟩ — a cheap local product given a cached adjoint and input, no backward pass needed. The cache is exact until weights or other masks move ("stale adjoint").
Box / vertex
Sources live in a box (each coordinate independently in [0,1]). A vertex is a corner (all coordinates 0 or 1). A linear function's maximum over a box is at a vertex, readable directly off gradient signs — no iteration.
Tilted / CVaR weighting
Given k sampled losses, weight them by softmax(loss/τ) instead of averaging — a soft maximum. τ→0 recovers the single worst sample; moderate τ optimizes the worst tail (CVaR). Converts "find the worst case by sequential search" into "draw candidates in parallel, up-weight the bad ones".
Optimistic / extragradient step
In adversarial (min-max) optimization, updating one player against a prediction of the other's next position — practically, extrapolating the sources along their optimizer momentum. A free substitute for an explicit catch-up (warmup) step.
Amortized adversary
A small trained network that predicts adversarial sources from activations in one forward pass, instead of finding them by per-step search. The search cost is paid during the predictor's training and amortized over all tokens and steps.
Staleness
A gradient computed against parameters from one step earlier. "Bounded staleness" designs accept one-step-old auxiliary gradients to break synchronization barriers.
Layerwise / chunkwise runs (macro-strategy)
Independent decomposition runs, each decomposing one site (layerwise) or a group of sites (chunkwise), submitted in parallel (pd-lm-layerwise-style arrays). Distinct from the failed layerwise loss: within each run, the adversarial loss is still joint over that run's sites; the rest of the model is the frozen target.

2 · The invariant kernel and the stable surface

Whatever the distributed strategy ends up being, each training step's adversary does the same five things on some set of ranks:

1. n_warmup × [ joint masked forward → backward to sources → Adam-PGD step ]   ← serial depth
2. one joint masked forward with the refined sources                            ← the loss that trains components
3. one backward producing component grads (+ CI grads, + source grads)
4. one more source step
5. persistent source state carried to the next step                             ← data-shaped memory

Every quantity a topology can vary — which ranks run this, what batch slice they see, where CI values come from, where the grads go — enters through the arguments of PersistentPGDState.warmup() / compute_recon_sum_and_n() / step(). The kernel itself is topology-blind. That gives a concrete robustness test for any proposed speedup:

Robustness test: can the change be expressed entirely inside param_decomp/metrics/persistent_pgd_{state,recon}.py (plus configs), without referencing the trainer, pools, portals, or rank layout? If yes, it survives every strategy — including the single-pool trainer you'd fall back to tomorrow. If it needs to know where ranks are or when other losses run, it's topology-coupled and will be rewritten with the next strategy.

Second principle, carried over: distribution buys width (parallel forwards, more ranks) and never depth (sequential inner steps). Item 1 above is pure depth. Speedups that convert depth → width compound with whatever parallelism the strategy of the week provides; speedups that merely cheapen each serial step are real but bounded; anything adding depth is dead on arrival.

3 · Constraints that persist across strategies

  1. The joint loss is load-bearing. The layerwise-PPGD experiment failed: restricting the adversarial loss to one site at a time underperforms joint masking, evidently because the adversary's distinctive job is cross-site compounding. So within whatever site-set a run decomposes, the loss that reaches the components must keep masking all of that run's sites jointly. The search for sources, the warmup objective, and the source storage are all fair game; the final loss is not. (Under one-site-per-run layerwise runs this constraint is trivially satisfied; it binds for chunk runs and any future joint run.)
  2. Data-shaped state is the enemy of strategy churn. Per-batch-per-position sources are sized by batch × seq × ΣC — the only training state that scales with data rather than parameters. Every topology change re-poses the questions of where it lives, how it's checkpointed, and whether a resume is layout-compatible (on the branch this surfaced as TB-scale per-rank shards and resumes tied to pool layout). Any move toward parameter-shaped (amortized head), low-rank, broadcast, or stateless (sampled) sources is itself a robustness win, independent of speed.
  3. The quality yardstick is procedure-independent. The PPGD eval metric (adversarial recon under optimized masks) doesn't care how training found its sources. Every idea below can be judged against the same baseline numbers, which is what makes the experiment plan in §8 coherent across strategy changes.

4 · Tier 1 — strategy-proof speedups IMPLEMENT IN CORE

All expressible inside the kernel surface; ordered by (confidence × payoff)/effort.

1.1 · Vertex warm start + optimistic extrapolation → n_warmup = 0/1

EFFORT: days · RISK: low (quality-checked by E4) · WHERE: PersistentPGDState.step / warmup

Two free upgrades to the source update, justified by the box geometry: (a) the final fused backward already yields source gradients; initialize the next step's effective sources at the vertex those gradients point to (coordinate-wise 0/1) rather than relying on incremental Adam drift — for a loss locally linear in the masks, that vertex is the one-shot solution the warmup steps are crawling toward. (b) apply an optimistic offset: read the effective source as clamp(r + γ·m̂) using the Adam momentum m̂ already stored in AdamPGDOptimizer._m — a prediction of the adversary's next move that substitutes for an explicit catch-up step. Together these attack the only reason warmup exists (sources lagging the components' last move) without any extra forward. The payoff is removing 2 of the 3 serial forward+backwards per step — the single largest portable win available. Catastrophic-overfitting caveats from the fast-adversarial-training literature apply when an adversary gets this cheap; the existing stochastic-recon term at equal coefficient is precisely the known mitigation, and E4 is the check.

1.2 · Tilted parallel sampling as the warmup replacement (depth → width)

EFFORT: ~week · RISK: medium (E5) · WHERE: a sibling of compute_recon_sum_and_n; config in the loss-metric union

Replace the serial inner loop with k parallel candidate mask draws — vertex-biased (Bernoulli spikes at mask = g), optionally centered on the persisted or predicted sources — scored under the joint loss, combined with softmax(loss/τ) tilting. Two properties make this the most strategy-robust idea on the list: it is stateless (constraint 2 dissolves — nothing to checkpoint, nothing layout-coupled, resume is trivial), and its cost is pure width — k samples batch along the existing sample axis (n_samples plumbing already exists) and parallelize over whatever ranks any strategy provides, which serial PGD steps never can. It also respects constraint 1 by construction: candidates are joint masks over all sites; coordination is explored by sampling rather than assumed away. Random-search attacks rivaling gradient attacks (Square Attack) plus the persistent-source result that 3 crude updates suffice both suggest k in the single digits may already match PGD-3 — at strictly better parallelism.

1.3 · Cheap warmup objective, exact final loss

EFFORT: days · RISK: low (final loss untouched) · WHERE: PersistentPGDState.warmup takes its own ReconstructionLoss

Whatever survives of the inner loop doesn't need the full KL over a 128k vocab to find a good ascent direction: run warmup against final-hidden-state MSE, a truncated KL (target's top-k tokens + tail bucket), or a random low-dimensional projection of the logit difference — and keep the exact fused KL only for the final forward that produces component gradients. This decouples warmup cost from vocab size for every model and every topology. Constraint 1 is respected: the surrogate touches only the search, never the loss the components see.

1.4 · Source parameterization: shrink or delete the data-shaped state

EFFORT: days–weeks per variant · RISK: per-variant (E3 calibrates) · WHERE: the PersistentPGDSourceScope union — already the designed extension point

The scope union is exactly where strategy-robust source compression belongs: broadcast_across_batch exists (one shared source per position; ~1000× memory, blunter adversary); add a low-rank scope (r = σ(P[b,t,:] · Q[:,c]), per-position latents decoded per component) and/or a parametric scope (r = ψ(g, h), a tiny shared map from CI value and inner activation). Each step down this ladder cuts memory and optimizer-state bandwidth, makes checkpoints parameter-shaped (constraint 2), and — because fewer degrees of freedom converge faster — reduces how much warmup is needed at all. The E3 post-mortem (how predictable are converged sources from (g, h)?) tells you how far down the ladder quality survives.

1.5 · Per-position triage for the search

EFFORT: days · RISK: low · WHERE: inside the warmup objective (masking the per-position loss)

The adversary finds ~nothing at positions where even random masks cause no divergence. Restrict warmup's objective (not the final loss) to the worst fraction of positions by per-position KL — computable from the stochastic-recon term in any trainer, or from the warmup's own first forward. With a gather-based head this makes warmup's unembed cost proportional to the surviving positions. Sharpens the old "smaller inner-loop batches" idea from random sub-batch to worst sub-batch.

1.6 · Amortized adversary head (the endgame)

EFFORT: weeks · RISK: high (min-max dynamics) · WHERE: alongside the CI fn; sources become a prediction, not state

The strategy-proof argument sharpened: an amortized adversary A_φ is structurally identical to the CI function — a small network mapping activations to per-component per-position values in [0,1], trained from gradients that arrive with the recon backward (sign-flipped). Every topology that can host a CI fn can host A_φ next to it, with zero additional comm pattern; checkpointing is parameter-shaped; "persistence" finally means something under streaming data (knowledge accumulates in φ, not in a buffer indexed by stale token positions). The layerwise-PPGD failure sets the expressivity bar: A_φ must be able to coordinate across sites, so for joint/chunk runs prefer a shared-trunk head over purely per-component-local heads. Sequence last, semi-amortized (predict, then one vertex refinement using 1.1's machinery), gated on E3.

5 · Tier 2 — keyed to parallel layerwise/chunkwise runs YOUR LIKELY MACRO-STRATEGY

These assume only one thing about the future: each run decomposes a site or chunk while the rest of the model stays the frozen target. That assumption is what the full-model joint-training regime broke — and your stated direction restores it. Everything here is robust to how each run is itself distributed (DDP width, batch size, node count), because the structure it exploits is per-run, not per-topology.

2.1 · Residual-start / prefix caching (keep; already written)

EFFORT: port from branch · RISK: none · WHERE: model wrapper, per-run

With all masked sites in one block, cache the clean residual entering that block once per batch; the target forward, every warmup forward, and the final recon forward run only the suffix. Already implemented on the branch (use_cached_residual); it's a property of the run shape, not the topology, so it ports anywhere. For mid-to-late-layer runs this alone removes ~l/L of every forward.

2.2 · Cached-adjoint local warmup (near-exact again)

EFFORT: ~week · RISK: low-medium · WHERE: warmup path, given one cached suffix backward per step

The biggest casualty of full-model decomposition, revived: when a run's masks touch one block, everything downstream is mask-free, so the suffix adjoint at the block output — obtained once per step, e.g. reused from the previous step's final backward — converts each warmup step into recompute the block + one einsum, with no suffix forward or backward at all. Combined with 1.1's closed-form vertex this collapses warmup to approximately the cost of one MLP block. Within-chunk coupling (gate/up → down) is the only approximation; the final exact joint forward catches it. This is the deepest per-run speedup available and is entirely invisible to the distribution layer.

2.3 · Suffix surrogates, amortized across the run array

EFFORT: weeks (one-time per target model) · RISK: medium (transfer quality; exact final loss as the catch) · WHERE: warmup objective, per-run

Each run's suffix is frozen and shared across every run in the array, every seed, every sweep on that target model. That makes a one-time investment rational: distill the suffix (layers l..L + head) into a small proxy — or simply quantize it — and run warmup attacks against the proxy, exact loss on the final forward. The distillation cost amortizes over the entire experimental program on that model, which is exactly the regime "parallel layerwise runs across an 8B model, repeatedly" creates. (Dead at full-model joint training; alive here.)

2.4 · Budget allocation across the array

EFFORT: config-level · RISK: low · WHERE: per-run YAML generation in pd-lm-layerwise

Runs are independent, so adversary hyperparameters can differ per run: early-layer runs (long suffixes, more compounding leverage, more expensive forwards) get more warmup/sample budget and benefit most from 2.2/2.3; late-layer runs may need n_warmup=0 and nothing else. The per-module hidden-acts MSE breakdown the PPGD metric already logs at eval is the signal to calibrate this from existing runs — turning the old "depth-weighted budget" idea into a YAML-generation policy rather than a runtime mechanism.

Open macro-question, flagged not relitigated: whether independently-decomposed sites compose into a good joint decomposition is the same question the layerwise-loss failure raises one level up. If a joint fine-tune stage ever follows the array, Tier 1 is what carries over to it; Tier 2 stays with the per-run stage.

6 · Tier 3 — topology-coupled: defer, with one exception WAIT FOR THE DUST

Everything that made the previous doc's headline — the one-step-stale adversary, dead-time/pipelined warmup, update-sharded block-coordinate refinement across pools, async adversary workers — needs to know where ranks are and when other losses run. Under a strategy in flux, building these now means rebuilding them; they are responses to a topology, so they should be designed after one stabilizes. Two things are worth keeping warm:

  • The staleness experiment (E1) — run it now anyway. Buffer the PPGD term's component/CI gradients by one step in the single-pool trainer (~20 lines, no distributed machinery) and measure quality. The implementation is throwaway; the result is not — "PPGD tolerates one-step-stale gradients: yes/no" is a fact about the optimization problem that derisks every future async/heterogeneous strategy in one shot, and it caps how much any future topology needs to care about the adversary at all.
  • Design the Tier-1 work to be async-ready for free. Stateless sampling (1.2) and the amortized head (1.6) happen to be the two adversaries that drop into an async or heterogeneous design with no extra machinery (nothing layout-coupled to migrate). No extra work needed — just a reason to prefer them at the margin.
