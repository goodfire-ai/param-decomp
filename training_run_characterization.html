Training Run Shape: 1B Target, 4B Causal Importance Function

This is a conceptual map of the current SPD/VPD training loop under the requested loss mix: layer-wise stochastic reconstruction, persistent PGD reconstruction, faithfulness with the weight-delta component enabled, and stochastic subset reconstruction. The key point is that this is not a normal LM pretraining step. The target LM is mostly frozen, the CI function is the largest trainable model, and one batch fans out into many masked full-model forwards.

Scope

4B is treated as the trainable causal-importance function. Component V/U parameters are additional unless included in that 4B.

Unit

Activation and mask costs scale with local tokens per rank: Brank x S. Global batch does not lower per-GPU activation pressure.

Pattern

For a 1B Llama-like target, I use 18 blocks x 6 decomposed sites per block = 108 sites, matching the current LM module pattern.

Evidence

Measured local baseline: 67M target, 660M trainable, H200, per-rank batch 8, peak 34.6 GB, of which 23.8 GB was activation/transient memory.

One Training Step: Required Dependency Graph

1. cache
Frozen target forward Produces target logits plus pre-weight activations for every decomposed site.
2. score
4B CI function Maps cached site activations to CI masks. Backward updates CI parameters.
3. adversary
PPGD warmups Extra recon forwards update persistent sources before the final PPGD loss.
4. losses
Masked recon fanout Subset loss runs sampled full-model forwards. Layerwise loss runs one forward per selected site/layer.
5. delta
Faithfulness + weight delta Materializes W_target - VU and may route an extra delta component through masked forwards.
6. update
Two gradient targets One backward for model/CI params, plus a separate gradient extraction for PPGD sources.

Fundamental serial points: target cache must precede CI; CI must precede stochastic masks and PPGD interpolation; PPGD warmups precede final PPGD loss; the optimizer step waits for all selected loss graphs.

Why HBM Disappears

Empirical anchor: the regular 67M-target run measured ~3 GB of activation/transient peak per local batch element at sequence length 512. At larger targets and a 4B CI function, the same categories dominate unless streamed or checkpointed.

Distributed Training Implications

DDP

Replicates the expensive state

Simple and bandwidth-efficient for small models, but every H200 carries the full 4B CI function, full optimizer state, full masks, and full local activation fanout. Adding GPUs mostly increases global batch.

ZeRO-1

Shards Adam state only

Useful because 4B trainable params imply ~32 GB of Adam moments. It does not shard params, grads, cached activations, layerwise graphs, masks, logits, or weight-delta transients.

FSDP

Shards params, grads, optimizer

The right first lever for 4B+ trainable state. Its risk is the multi-forward loop: repeated gather/reshard and weight-delta materialization must be aligned with decomposition-site boundaries.

Work splitting

Best target is loss fanout

Layerwise samples and stochastic samples are mathematically additive. They are natural candidates for streaming backward, parallel loss evaluation, or assigning subsets of sites/samples to ranks.

Activation memory is not sharded by ordinary data parallelism. Per-rank batch size and sequence length are the main knobs. FSDP solves resident state, not the layerwise graph pileup.
The CI function creates a global coupling point. If CI reads all site activations and emits all site importances, naive layer or tensor parallelism has to move activations or scores across partitions.
PPGD is stateful but mostly separable. Per-batch-per-position sources are local to rank in the current pattern; shared-source scopes require synchronization of source gradients.
Faithfulness is parameter-space work. It does not need batch activations, but the weight-delta component injects target-sized delta tensors and extra delta-path matmuls into masked forwards.

What Is Fundamentally Required

Resident: frozen target weights; trainable V/U components; trainable CI function; gradients; optimizer state; PPGD source tensors and any source optimizer state.

Per step: target logits, cached pre-site activations, CI outputs, stochastic masks, routing masks, weight-delta tensors, and retained forward graphs for every loss term participating in the final backward.

What Scales With Batch

Everything shaped like [Brank, S, ...]: cached activations, CI activations, CI scores, masks, PPGD sources under per-position scope, target logits, component activations, and delta-path outputs.

Increasing global batch by adding ranks only helps if the per-rank batch stays fixed and the fixed state has already been sharded enough to fit.

Most Sensitive Knobs

M_layerwise: exact layerwise loss cost scales linearly with selected sites.

n_mask_samples: multiplies subset and layerwise fanout.

PPGD warmups: add serial forward+grad source steps.

CI checkpointing: trades compute for the largest activation savings seen so far.

Practical Reading Of The Example

A 1B frozen target plus 4B trainable CI is not fundamentally impossible on H200s, but it is only comfortable if resident state is sharded and the loss fanout is handled deliberately. The resident-state problem points toward FSDP or equivalent sharding. The per-step activation problem points toward checkpointing, streaming loss terms, reducing or sampling the layerwise fanout, and keeping per-rank token count conservative.

The non-negotiable shape is: one target-cache pass, one global CI pass, multiple masked reconstruction passes, parameter-space faithfulness, and a PPGD source update path. The architectural constraint is that the CI pass couples all decomposed sites through a single trainable function, while the reconstruction losses create many independent masked evaluations whose gradients all flow back through the same CI outputs.
