End-to-End Run Flow

There is one user-facing CLI — pd-run — and one training function — run_pd(). pd-run submits a SLURM job by default; each task invokes the internal worker module param_decomp.experiments._worker, which loads the driver and calls run_pd. pd-run --local skips SLURM and runs the worker in-process. A notebook can also import run_pd directly, bypassing drivers entirely.

What happens, in order

  1. pd-run resolves its input source into (name, driver_path, config_dict): a built-in experiment name (looked up via discover_experiments()), --config_path + --driver for a custom recipe, or --rerun PATH reading driver + config from a saved run_metadata.yaml.
  2. With --local, pd-run calls _worker.run_experiment(driver_path, config_dict) in this process. Otherwise it calls launch_slurm(...), which expands any sweep grid, creates a git snapshot branch, and submits a SLURM array. Each array task invokes python -m param_decomp.experiments._worker --run_spec_json ....
  3. _worker.run_experiment loads the driver, validates the config via driver.config_type.model_validate(...), builds the PDTarget and train/eval dataloaders, calls driver.artifacts(config, target), and constructs a RunSpec(driver=driver_path, config=config_dump).
  4. run_pd() creates PARAM_DECOMP_OUT_DIR/decompositions/<run_id>, writes run_metadata.yaml and all artifacts via save_pre_run_info(), starts W&B if configured, then trains.
  5. A direct run_pd() call from a notebook skips the driver entirely. The run spec defaults to RunSpec(driver=None, config={"pd": pd_config.model_dump()}); the run then reloads via load_component_model(path, target=...).

Saved Run and Reload

Reload picks up where the first diagram left off. Its starting box — Saved run directory — is the same green decompositions/<run_id>/ the training flow ended with. From there, three calls turn that directory back into a working ComponentModel: PDRun.from_path parses the run spec, load_target rebuilds the target via the driver, and load_model stitches the checkpoint onto it.

load_component_model(path) is shorthand for steps 1–3 chained together: PDRun.from_path(path).load_model().

When a driver is present, build_target and build_dataloaders get called with run_dir=pd_run.path so they read bundled artifacts (target_model.pth, target_train_config.yaml) instead of re-fetching from external sources.

No driver in the run spec? The run came from a direct run_pd() call. You must pass target=... to load_component_model(); PDRun.experiment_config will be None for such runs.

The Three Concerns

Algorithm config

PDConfig owns losses, optimizer, schedules, CI architecture, module patterns, W&B. It never references a target model or dataset.

Experiment recipe

An ExperimentConfig subclass adds where the target comes from and what the data is. A driver turns the recipe into runtime objects: a PDTarget and dataloaders.

Runtime orchestration

One entry point (pd-run, on SLURM by default or in-process with --local) and one notebook escape hatch (direct run_pd) converge on a single training function and produce a saved run that PDRun.from_path / load_component_model can reload.

Entry Points

Entry Source When to use
pd-run <experiment> experiments/runner.py Run a built-in experiment by name on SLURM. Auto-resolves driver + YAML.
pd-run --config_path PATH --driver DRV experiments/runner.py Run a custom YAML with an explicitly named driver.
pd-run --rerun PATH-OR-URL experiments/runner.py Rerun a saved run (local path or wandb URL). Driver + config are read from the run's run_metadata.yaml.
pd-run ... --local experiments/runner.py Run in-process; skip SLURM and the git snapshot. Required off cluster. Disables --sweep and --dp.
pd-run ... --sweep [--n_agents N] scripts/run_slurm.py SLURM array sweep over the parameter grid in param_decomp/scripts/sweep_params.yaml (or a custom file). Built-in experiments only.
pd-run ... --dp N utils/compute_utils.py Multi-GPU DDP (single-node up to 8 GPUs, multi-node when divisible by 8).
python -m param_decomp.experiments._worker experiments/_worker.py Internal: the per-task entry point that each SLURM array task invokes.
run_pd(config, target, ...) run_pd.py Notebook / scripting: skip drivers, supply your own PDTarget + dataloaders. Pair with load_component_model(path, target=...) for reload.
load_component_model(path) / PDRun.from_path(path) saved_run.py Reload a saved run.

The shell entry point is wired in pyproject.toml:

pd-run = "param_decomp.experiments.runner:cli"

Object Catalogue

PDConfig

param_decomp/configs.py

The PD algorithm config. Owns losses (loss_metrics), eval metrics (eval_metrics), CI function (ci_config), module decomposition patterns (module_info), LR schedule, batch sizes, seed, W&B project. Never references a target model or dataset.

ExperimentConfig

experiments/driver.py

Base class subclassed by each experiment. Only required field is pd: PDConfig; subclasses add target and data. Pure data, no I/O.

  • LMExperimentConfig(pd, target: LMTargetConfig, data: LMDataConfig)
  • TMSExperimentConfig(pd, target: TMSTargetConfig, data: TMSDataConfig)
  • ResidMLPExperimentConfig(pd, target, data)

ExperimentDriver

experiments/driver.py

Stateless adapter: turns an ExperimentConfig into runtime objects.

class ExperimentDriver[ConfigT: ExperimentConfig](Protocol):
    name: ClassVar[str]
    config_type: ClassVar[type[Any]]

    def build_target(self, config: ConfigT, *, run_dir: Path | None = None) -> PDTarget: ...

    def build_dataloaders(
        self, config: ConfigT, *,
        train_batch_size: int, eval_batch_size: int,
        dist_state: DistributedState | None = None,
        device: str = "cpu",
        run_dir: Path | None = None,
    ) -> tuple[DataLoader[Any], DataLoader[Any]]: ...

    def artifacts(self, config: ConfigT, target: PDTarget) -> dict[str, Any]: ...

When run_dir is set, the driver should prefer locally bundled files over fetching from W&B. Drivers are loaded by import path via load_driver("pkg.module:Driver").

PDTarget

models/batch_and_loss_fns.py

The bundle run_pd consumes:

  • model: nn.Module — the target model whose parameters we decompose.
  • run_batch — function (model, batch) → output. Helpers: run_batch_passthrough, run_batch_first_element, make_run_batch(output_extract).
  • reconstruction_loss — function comparing target vs reconstructed outputs. Helpers: recon_loss_mse, recon_loss_kl.
  • tied_weights: list[tuple[str, str]] | None — optional weight-tying pairs.

RunSpec

param_decomp/run_spec.py

@dataclass
class RunSpec:
    driver: str | None             # import path; None for notebook/no-driver runs
    config: dict[str, Any]         # full experiment config dump
    wandb_project: str | None = None
    wandb_run_name: str | None = None
    view_meta: dict[str, Any] = field(default_factory=dict)

Read/write helpers: RunSpec.from_file(path), .write(path), .from_dict(...).

TaskSpec

param_decomp/scripts/run_slurm.py

Per-task payload built by the launcher: a RunSpec plus a pre-generated run_id. One task spec per array task; the launcher serializes the run spec as --run_spec_json '{...}' for the worker.

Artifacts

A dict[str, Any] returned by the driver's artifacts(config, target). Each (filename, data) pair is written into the run dir by save_pre_run_info. Typical contents:

  • TMS / ResidMLP: target_model.pth, target_train_config.yaml.
  • ResidMLP also: label_coeffs.json.
  • LM: empty (target is reloaded from HuggingFace by the driver).

These files are saved beside run_metadata.yaml by run_pd.

PDRun

param_decomp/saved_run.py

Handle to a saved run. Loads the run spec eagerly; driver/config lazily.

@dataclass
class PDRun:
    path: Path
    spec: RunSpec
    checkpoint_path: Path

    @classmethod
    def from_path(cls, path: ModelPath) -> "PDRun": ...

    @classmethod
    def spec_from_path(cls, path: ModelPath) -> RunSpec: ...   # spec only, no checkpoint

    driver:             ExperimentDriver | None   # cached_property
    experiment_config:  ExperimentConfig | None   # cached_property, validated via driver.config_type
    pd_config:          PDConfig                  # property
    name:               str                       # driver.name or "custom"

    def load_target(self) -> PDTarget: ...
    def load_dataloaders(self, *, train_batch_size, eval_batch_size, ...) -> tuple[DataLoader, DataLoader]: ...
    def load_model(self, target: PDTarget | None = None) -> ComponentModel: ...

Experiment Discovery

experiments/discovery.py

Built-in experiments are discovered by walking param_decomp/experiments/<kind>/. A subdir qualifies as a "kind" iff it contains an experiment.py. Each [!_]*.yaml next to that file becomes a registered experiment.

  • Name = YAML stem with trailing _config stripped (tms_5-2.yaml → tms_5-2).
  • Driver path = param_decomp.experiments.<kind>.experiment:Driver — strict convention, not configurable. 
@dataclass(frozen=True)
class DiscoveredExperiment:
    name: str          # e.g. "tms_5-2"
    kind: str          # e.g. "tms"
    config_path: Path  # repo-relative path to the YAML
    driver_path: str   # "param_decomp.experiments.tms.experiment:Driver"

Duplicate names across kinds raise an assertion.

SLURM Launcher Flow

When pd-run isn't given --local, it calls launch_slurm in param_decomp/scripts/run_slurm.py. The launcher produces one or more SLURM tasks; each task invokes python -m param_decomp.experiments._worker with a driver import path and a JSON config blob.

StageBehavior
Input resolution runner._resolve_source turns the CLI flags into (name, driver_path, base_config). Exactly one of positional <experiment>, --config_path, or --rerun must be set.
Sweep expansion Loads sweep_params.yaml (or a custom file), merges global: with per-experiment params, generates the Cartesian product, applies each combo via apply_nested_updates to a deep copy of the base config. Local expansion — not W&B sweep agents.
RunSpec Per-task payload: a RunSpec plus a pre-generated run_id. The launcher stamps wandb_project onto each run spec before submission.
Git snapshot One snapshot branch per launch for reproducibility (especially multi-node).
Command generation get_command() dispatches on n_gpus: plain python -m param_decomp.experiments._worker, single-node torchrun --standalone --nproc_per_node=N, or multi-node srun + torchrun.
Submission Single SLURM script for one job; SLURM array (capped by --n_agents) for multiple.

Command shapes

# Single-process
python -m param_decomp.experiments._worker \
  --run_spec_json '{...}' \
  --launch_id launch-... --run_id p-...

# Single-node DDP
torchrun --standalone --nproc_per_node=4 --master_port=... \
  -m param_decomp.experiments._worker --run_spec_json '{...}' --run_id p-...

The run spec JSON contains the driver import path, full config, W&B fields, and any view_meta labels.

Custom Drivers

You don't need to touch core code to add an experiment — just write a driver and point pd-run at it: 

pd-run --driver my_pkg.my_exp:MyDriver --config_path my_config.yaml

A driver is anything that satisfies the ExperimentDriver Protocol. See experiments/tms/experiment.py for a complete reference:

The worker records the supplied driver import path into RunSpec.driver so the run is reloadable later via the same code path as built-ins.

If you don't need pd-run, sweeps, or post-processing tooling, call run_pd directly and skip drivers entirely — see the README's "Custom experiments" section.

Saved Run Layout

Saved runs live under PARAM_DECOMP_OUT_DIR/decompositions/<run_id>/ (cluster: /mnt/polished-lake/artifacts/mechanisms/param-decomp/; local: ~/param_decomp_out/). 

decompositions/<run_id>/
├── run_metadata.yaml          # RunSpec: driver, config, wandb fields, view_meta
├── model_<step>.pth           # PD checkpoints (one per save_freq + final)
├── target_model.pth           # artifact: TMS / ResidMLP only
├── target_train_config.yaml   # artifact: TMS / ResidMLP only
├── label_coeffs.json          # artifact: ResidMLP only
└── sweep_params.yaml          # only if launched with --sweep

A typical run_metadata.yaml:

driver: param_decomp.experiments.lm.experiment:Driver
config:
  pd:
    seed: 0
    loss_metrics: {...}
    ci_config: {...}
    module_info: [...]
    ...
  target: {...}
  data: {...}
wandb_project: param-decomp
wandb_run_name: seed=0
view_meta: {}

Reload usage

pd_run = PDRun.from_path("wandb:entity/project/runs/abc123")
pd_run.spec               # RunSpec
pd_run.pd_config          # PDConfig (always available)
pd_run.driver             # ExperimentDriver | None  (None for notebook runs)
pd_run.experiment_config  # ExperimentConfig | None — parsed via driver.config_type
target = pd_run.load_target()        # driver.build_target(cfg, run_dir=path)
loaders = pd_run.load_dataloaders(...)
model = pd_run.load_model()          # ComponentModel.from_checkpoint(...)

# Shortcuts
model = load_component_model("wandb:entity/project/runs/abc123")               # driver-backed
model = load_component_model("/path/to/run", target=my_target)                 # notebook-style run
