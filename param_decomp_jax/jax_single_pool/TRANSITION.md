# Fully-JAX: one framework, train and analyze

The settled plan (decided 2026-06-16, Dan + Oli). VPD becomes a **single-framework JAX**
stack: train AND analyze in JAX. Torch is **retired as the running code** but **kept in
git as the battle-tested oracle** — JAX conforms to torch's semantics, never redefines
them. `SPEC.md` (grounded in torch) stays the contract. This doc is the structural plan;
it supersedes the earlier "keep torch as the consumption/export layer" plan, which is
dead.

## 1. The decision

- **One framework: JAX.** Both training and analysis run in JAX. There is no permanent
  torch consumption layer, no dual-backend seam, no `Arr`-generic protocol. `DecomposedModel`
  is simply THE model interface (no `Arr` TypeVar).
- **Built on `feature/jax`, not `main`.** All work lands on `feature/jax`; the branch is
  squash-merged to `main` **once, at the very end** (phase 4). The cutover is
  cold-turkey — there is no torch stopgap kept alive on `main` in the interim.
- **Torch = oracle, preserved in git** (not deprecated-as-wrong). Torch is the
  battle-tested reference for *correctness*. JAX must **conform** to it; numeric seams
  **default to MATCHING torch**, and any divergence is deliberate and documented in
  `SPEC.md`. Two tags pin the oracle:
  - `torch-oracle` — single-pool torch core at its HEAD (the `param_decomp/` trainer the
    SPEC is grounded in).
  - `torch-oracle-npool` — the `feature/fsdp-lm-trainer` n-pool lineage: the runnable
    `ChunkwiseSubsetReconLoss` and the n-pool reference the production constants and
    stochastic-recon fixtures come from.
  Goldens are regenerated by resurrecting a tag in a torch-venv worktree
  (`git worktree` the tag → torch venv → run to regenerate the reference), not by keeping
  torch code in HEAD.
- **The JAX→torch export bridge is DEAD.** We do **not** make torch load JAX runs.
  `jsp-export`'s torch-`ComponentModel` shape goes away; JAX consumers read the **orbax
  checkpoint + `DecomposedModel`** directly. The whole `#746`–`#752` export-bridge cluster is
  closed as moot.
- **Dropped features stay dropped for now** (revisit in JAX later, as backlog — not part
  of the numbered roadmap):
  - **Attribution graphs** — `dataset_attributions/`, `graph_interp/`,
    `topology/gradient_connectivity.py`, the app's graph/attribution routers.
  - **Circuit-opt / model editing** — `optim_cis.optimize_ci_values`,
    `editing/editable_model.py`.
  - **App PGD intervention** — the interactive-autodiff path; the app becomes a
    **read-only viewer**.
  These may turn out *easier* in JAX (vmap + grad compose cleanly), so they are a backlog
  item, not a permanent cut — but they are out of scope for the cutover.

## 2. Canonical interface (JAX-only)

Promote what already exists — pure-functional, state-injected. There is no torch
counterpart to keep in sync.

- **`DecomposedModel`** (`lm.py`): ordered `sites` + `clean_output` / `site_inputs` /
  `masked_output` / `weight_deltas` over `(frozen, vu)` pytrees.
- **`CIFn`** (`ci_fn.py`): `site_inputs -> (ci_lower, ci_upper)`. (SRP: model and CI are
  separate concerns; a run is the pair + frozen target.)
- **Dispatch lives only at the edges:** one `load(run) -> Decomposition` and one
  `export(state) -> orbax`. Nothing else knows architecture/layout.
- **Generic model I/O** *(in progress)*: the trainer is generic over **input** (dict or
  tuple), **output** (tuple), and **recon loss** (pluggable; KL-on-logits is the default),
  while keeping the `(B,T)` residual as the **fixed waist** — there is no batch-dim
  generality. A synthetic **dict-in / tuple-out / MSE** fixture locks this contract.

## 3. The roadmap — four phases

The four phases are sequential commitments on `feature/jax`. Phases 1 and the generic-I/O
work are landing now; 2 is in progress; 3 and 4 follow.

### Phase 1 — Train in JAX (**DONE**)

A standalone, torch-free training runtime.

- **Self-contained runtime.** `jsp-train` + trainer / losses / eval import nothing from
  torch and nothing from the adjacent consumer submodules.
- **Recon unified on one chunkwise plan.** The historical `all_sites` / `per_site` recon
  variants are the **N-site / 1-site endpoints** of a single chunkwise recon plan (see
  `LOSS_PARITY_DESIGN.md`); the loss is always on final logits.
- **Config read directly from `param_decomp_config`.** The torch-free pydantic schema is
  the shared foundation; the runtime reads it directly. `torch_config.py` (the NamedTuple
  conversion layer) is deleted.
- **Torch trainer retired from HEAD** (lives at `torch-oracle`): `param_decomp/optimize.py`
  (`Trainer`), `train_step.py`, `faithfulness_warmup.py`, the `param_decomp/metrics/` tree
  (loss metrics incl. PPGD), and the torch training drivers.
- **Validated:** standalone JAX training smoke — save **and** resume at production
  per-rank shape **PASSED** (run `p-f20f1b39`, jobs 66697 / 66698; resumed @ step 40 and
  continued the same trajectory).

### Phase 2 — Analyze in JAX (*in progress*)

Port the consumers to read JAX runs **natively** (orbax + `DecomposedModel`), in dependency
order:

1. **Harvest** — the keystone; component-statistics collection everything else reads.
2. **Clustering** — consumes harvest output.
3. **Autointerp** — harvest-based, so nearly free once harvest lands.
4. **Slow / offline eval metrics** — the eval-consumer side.

The read-only **app** may land here or in phase 3, depending on how harvest/eval shake
out.

### Phase 3 — App (read-only) in JAX + shed torch

- Port the app's **browse / harvest / eval / cluster** views to read JAX runs. There is
  **no attribution and no intervention** in the app — those are dropped (§1).
- As each JAX replacement lands, **delete** the corresponding torch model classes and
  consumer modules. Torch leaves HEAD module-by-module, behind its replacements.

### Phase 4 — Cutover

- **torch→jax adapters** so old SOTA torch runs still load into the JAX consumers — the
  existing torch run corpus is not orphaned.
- **Final torch deletion**, then the **one big squash-merge `feature/jax → main`**.

## 4. Dependency cuts — phase-1 runtime

"Self-contained" constrains the **runtime** (the thing that runs on GPUs), not the
login-node launcher. `lab → param_decomp_jax` is a fine dependency direction; only
`param_decomp_jax → adjacent` is forbidden. `run.py` (`jsp-train`) is already
runtime-clean.

| bucket | today | action |
|---|---|---|
| **Config** | `param_decomp_config` (canonical, torch-free) **+ `torch_config.py` conversion** | **Keep `param_decomp_config`** as the shared foundation; **read the schema directly**; **delete `torch_config.py`** (it only translated the canonical schema into internal NamedTuples — gone). |
| **Launcher + infra** | `pd-jax-lm` (lab-side, login-node submission) + `param_decomp_lab.infra` (slurm / git-snapshot / wandb) | **KEEP as-is.** It is the submission *wrapper*, not the GPU runtime — runs in the lab venv and reuses battle-tested infra (the two-venv split is already the `pd-jax-lm` design). `lab → jax` is fine. |
| **Torch parity refs** | `param_decomp.*` + lab `vendored` / `three_pool` / `batch_and_loss_fns` — **only in test/export tooling** (golden generation, the rotted `verify_export_torch.py`) | **Freeze the goldens** as committed artifacts; **drop the torch-reference generation** and the rotted verifier. Fixtures stay; the torch code that produced them goes (severs the last `param_decomp_jax → torch` import). |
| **Logging / sink** | in-package already (`run.py` `MetricsSink`) | keep |

Vendored targets: `vendored_jax/` (Llama, GPT-2) is already self-contained — keep; drop
the torch-vendored *parity* imports.

## 5. Invariant grounding — reconcile against the oracle

The contract is unchanged: `SPEC.md` is grounded in torch (`torch-oracle` /
`torch-oracle-npool`), JAX conforms. Reconciling the pre-existing parity issue set against
the fully-JAX plan:

- **Numeric seams default to match-torch.** The CI-numeric and cosine/grad-clip seam
  decisions **default to MATCHING torch** (the oracle); any divergence is deliberate and
  documented in `SPEC.md`. Decided per-seam, not auto-closed. The wave-1 SPEC amendments +
  tests already merged stay.
- **Export-bridge issues are closed as moot** — the `#746`–`#752` JAX→torch cluster, plus
  every attribution-graph / app-autodiff parity issue (those features are dropped).
- **Consumer-port issues are re-homed to phase 2/3** — harvest / clustering / autointerp /
  eval parity moves with its phase.
- **Goldens are the durable oracle artifact.** They are committed; regenerate by
  resurrecting a tag in a torch venv (§1). No torch reference generator lives in HEAD.

## 6. Deferred (kept, outside the numbered roadmap)

- **Dropped-then-maybe-revisited in JAX:** attribution graphs / `dataset_attributions` /
  `graph_interp`, circuit-opt / model editing, app PGD intervention (§1). Backlog, not
  numbered — possibly easier in JAX (vmap + grad).
- **Non-vendored targets:** TMS / ResidMLP are tiny ports; generic HF `from_pretrained` is
  the one open-ended tail (production vendored Llama is covered).
- **Recon seams already refused in spec:** hidden-acts / attn-pattern recon, `nsc` scope,
  sigmoid-source / sign parameterization (see `LOSS_PARITY_DESIGN.md`).
